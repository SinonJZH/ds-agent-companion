# 测试设计

本文档只描述当前最新状态，修订记录见 [revisions.md](revisions.md)。

## 总体分层

按确定性分层，LLM 质量类内容不进测试金字塔：

| 层        | 内容                                                  | 运行方式                       |
|-----------|-------------------------------------------------------|--------------------------------|
| 单元      | 确定性纯逻辑与架构不变式                              | 默认套件，离线快跑             |
| 集成      | FakeLLM 驱动的引擎 loop、真实 SQLite、ConnectRPC 服务 | 默认套件，离线快跑             |
| 并发      | asyncio 并发语义（会话串行、排队、WAL）               | 默认套件，离线                 |
| embedding | 真 fastembed + 真 sqlite-vec 表                       | marker `embedding`，离线确定性 |
| live_api  | 真调 DeepSeek 的契约钉子                              | marker `live_api`，本地手动    |
| eval      | 基线问题集重放、查重阈值校准                          | 独立 runner，本地手动          |

原则：

- 覆盖率不设硬指标；替代原则是架构文档中每条不变式必须有对应测试，对齐关系即验收标准。
- eval 层定位为独立命令 + 独立报告（可 diff 两次运行），跑的时机是改阈值 / 调提示词 / 换嵌入输入时；它有 API 成本且结果非确定，不进
  pytest 与 CI。
- 不做的事：不在单测中断言 LLM 输出质量；不 mock sqlite-vec 内部实现（tmp 文件建真表）；设置类页面不做浏览器级测试。

## 可测性约束（架构级要求）

四个注入点，所有模块经构造函数接收依赖，测试据此替换：

- 时钟：全部时间取值经注入的 `clock()`，禁止直接调用 `datetime.now()`；
- LLM 客户端：底层 httpx 客户端可注入（openai SDK 经 `http_client` 参数），测试用 `httpx.MockTransport` 拦截；
- 嵌入函数：记忆模块收 `embed(texts) -> ndarray`，单元层注入手工构造向量（可精确构造任意 cosine 距离），真实 fastembed 仅
  embedding 层使用；
- 数据库路径：全部经构造函数传入，测试用 tmp 目录建真库。

## 后端测试

### 单元层（默认）

测架构文档中的不变式，高价值用例：

- 提示词组装：golden 快照只存结构指纹（块的顺序、存在性、场景变体选择、尾部块位置），不存内容全文——块内容是用户可编辑的数据，会合法变动。专测一条前缀缓存稳定性：同一会话快照内连续两轮组装，尾部块之前的前缀字节级相同。
- 分区不变式：hypothesis 属性测试——随机混合分区的写入序列 × 随机会话分区，断言公开会话注入内容（含 AI 检索工具返回路径）永不含隐私条目。
- 整轮裁剪：裁剪不拆散一轮的 `content` / `reasoning_content` / `tool_calls` + 工具结果整体；裁剪后带 tools 会话的历史仍完整携带思维链。
- 晋升无空窗：虚拟时钟推进下，任意时刻条目要么在 24h 日视图内、要么已晋升进周层；含各层软/硬上限（周记软 30 / 硬 40）边界。
- 时间语义：UTC epoch ↔ IANA 时区日界线换算、夏令时跨越、"某一天"查询的区间换算、配置时区变更后的历史重切片。
- 存储 append-only：对笔记表 DAO 做横贯断言——任何代码路径都不 UPDATE / DELETE。
- 依赖方向：用 import-linter 机械执行架构文档的依赖方向约束（LLM 与插件互不感知等）。
- token 预算：常驻注入预算封顶与截断顺序。

### 集成层（默认，离线）

- FakeLLM 为一等测试基础设施：实现 LLM 模块的同一事件流接口，脚本化回复序列（纯文本 / tool_call 链 / reasoning_content /
  流式分片 / 429 与超时 / 上下文超限），驱动完整 agent loop、插件分发、结果回填、重试路径。
- 插件安全逐条测试：隔离标记防提示注入、危险操作确认门、执行超时。
- ConnectRPC 服务层经 ASGI 测试客户端直打（含 server-streaming envelope 语义），同时充当前后端契约的后端侧验证。

### 并发层（默认，离线）

同会话串行处理与并发触发排队、后台任务与引擎经 WAL 并发访问同一库、调度项重启不丢；用真实 event loop + 可控 await
点测试，不只测纯逻辑。

### embedding 层（marker `embedding`）

真 fastembed + 真 vec0 虚拟表：检索排序三因子合成（相关度 × 新近度衰减 × 重要度）、命中强化、查重的真实距离分布。模型缓存后离线确定性。

### live_api 层（marker `live_api`，手动）

极少量真调 DeepSeek 的契约钉子，发布前手动跑，不进任何自动触发：

- 带 tools 请求必须全量回传 `reasoning_content`，否则 400；
- 经 usage 缓存命中字段实测前缀缓存真实命中（守护提示词稳定前缀设计）。

### eval 层（独立 runner）

基线问题集重放与查重阈值校准（阈值与灰区带宽配置变更后重放对比），本地手动运行，报告供人工对比判断变化方向。

## 前端测试

前端为薄客户端，业务逻辑几乎全在后端，测试投入向后端倾斜，守住三件事：

- 组件单测：基于 connect-es 生成客户端 mock（mock transport，拦截点在生成的 service 边界，组件不感知
  HTTP）。核心场景：server-streaming 分片到达 → 按消息条目分项节流更新 → markdown 流式渲染 → thinking
  可折叠区块；场景切换时对话流 / 帖子时间线视图形态；长会话虚拟滚动。
- 安全测试：LLM 输出与插件带回内容在前端为不可信输入——断言 markdown 渲染关闭原始 HTML 或有 sanitize 步骤，`<script>`
  等不被执行。
- token 对比度校验：对 token 定义文件做纯断言测试（非 DOM 测试），全组合 ≥4.5:1、正文组合 ≥7:1，纳入默认套件。

E2E 仅一组 Playwright 冒烟（3~5 条）：引擎 headless 启动（LLM 注入 FakeLLM，引擎留测试入口）+ 静态托管前端构建产物，跑「发消息 →
流式回复渲染」「切人设 / 场景」「记忆页打开」等主链路。各设置页不做浏览器级测试，组件级足够。

## 契约与 CI

- proto 为两侧唯一契约：buf breaking 对 git ref 检测破坏性变更，进默认 CI；前端生成代码由 lockfile 钉住。
- 默认 CI（每次 push / PR）完全无 secrets——fork PR 结构性拿不到 secrets，默认工作流必须纯离线：后端默认套件、前端单测 +
  对比度校验、双端 build、buf breaking；embedding 层经 actions/cache 按模型版本缓存模型后纳入默认 CI。
- live_api：本地按需为主；如需 CI 位置则独立 workflow_dispatch 手动触发工作流（secrets 仅手动触发时可见、限并发、token
  用量压到最小），不放 schedule——真 API 非确定，定时红了基本是噪音。
- eval：纯本地手动，报告需人工阅读判断。
- 开源卫生：测试 fixture 与基线问题集随仓库公开，一律用合成内容构造，禁止真实私人对话与人名 / 宠物名 / 职业等真实个人数据。
