# 项目架构

本文档只描述当前最新状态，修订记录见 [revisions.md](revisions.md)。

## 项目定位

通过调用 DeepSeek API 让模型进行角色扮演，陪伴用户对话。单用户本地运行。

## 总体架构

对话引擎是编排核心；主调度层承接所有定时/条件触发与后台任务；全部持久化收敛到单一 SQLite 存储。

```
交互层 ──┐
         ├──→ 对话引擎 ──→ 提示词模块 ──→ 记忆模块（检索/注入）
主调度层 ─┘    │                            ↑
              ├──→ LLM 模块（API 调用）      │
              └──→ 插件模块（tool 执行）     │
                                           │
后台任务（蒸馏/晋升/压缩/心境抽取/记忆卫生）──读写──┘

        所有运行数据落盘于存储层（SQLite）
```

依赖方向约束：LLM 模块与插件互不感知；提示词模块不知道 LLM 的存在；记忆模块只被提示词组装（读）、后台任务（写）和 AI
记忆工具（读写，经引擎分发）访问。

## 模块划分

### 对话引擎

编排核心，持有会话状态，执行完整的 agent loop：组装提示词 → 调用 LLM → 解析 tool_call → 执行插件 → 结果回填 → 循环直至产出最终回复。

- 用户主动会话与调度层触发的主动会话（定时/条件唤醒）汇入同一引擎。
- 会话开始时取记忆注入快照，会话内注入集合固定，超长会话可超时刷新。
- 上下文裁剪按整轮进行（user + assistant 的 content/reasoning_content/tool_calls + 工具结果整体进出）。
- 单进程 asyncio；同一会话串行处理，并发触发排队。
- token 超限时的裁剪从最旧会话轮次开始（初版方向）。

### 主调度层

- 三种写入方（用户手动 / LLM 经工具 / 插件直接写）共用统一的调度项 CRUD 接口；调度项持久化，重启不丢。
- 每个调度项记录创建来源，可审计；设数量与频率上限。
- 内置后台任务：每小时蒸馏（把新增对话蒸馏为今日条目 + 对即将滑出 24h
  窗口的条目做晋升判断，空闲时段跳过）、周/月/年压缩、每日心境抽取、记忆卫生（向量条目查重合并、状态卡对账与低质清理）。
- 回忆触发为内置触发类型：候选源为条目关联日期（周年、纪念日）或高重要度久未访问条目，命中即以该条目为上下文发起
  `private_chat` 主动会话。
- 主动发帖为内置触发类型：定期或按条件触发 `sns_post` 场景会话，产出发布到时间线；是 SNS 场景唯一的主动入口，其余定时/条件触发的主动会话均归
  `private_chat`。
- 无时效性任务优先排入谷价时段。
- 触发后调用对话引擎执行对话。

### 提示词模块

对组装逻辑封闭，对外仅暴露 `build(scene, context) → messages`，为纯函数：同样的场景与状态永远组装出同样的提示词。

- 提示词块三级归属：
    - 全局层：安全底线等，无条件注入；场景变体与人设包只能加严，不能删除或放松；
    - 场景默认层：按场景切换的块（如 SNS 场景的严格发布限制 vs 私聊的宽松限制）；
    - 人设包层：角色私有内容。
- 槽位 + 场景变体：每个槽位（如 `safety_policy`）含多个场景变体，按场景取用，缺省落默认变体；选择（哪些块适用）与排序（放在哪里）是两个正交机制。
- 场景枚举是引擎↔提示词模块契约的一部分，初版：`private_chat` / `sns_post` / `sns_reply`
  ；扩展即契约变更，两侧同步。场景枚举只承载对话场景，后台任务调用走独立任务模板入口（见下）。
- 场景严格度不设独立等级机制，由三个既有机制组合表达：分区注入规则（`private_chat` 注入公开+隐私，`sns_*` 只注入公开）、场景默认层槽位变体（
  `sns_*` 取加严变体：篇幅、频率、隐私保护、公开场合言行）、场景级模型配置（`sns_*` 收窄 tools）；各变体具体文案随提示词编写阶段落地。
- 后台任务（蒸馏、晋升、压缩、心境抽取、查重仲裁）的 LLM 调用走本模块第二入口 `build_task(task, data)`
  ：任务模板与对话场景同模块管理，组装结果同样落盘日志；不进场景枚举契约，模型配置见 LLM 模块。
- 组装顺序按变动频率排列（稳定在前，配合 DeepSeek 前缀缓存）：人设 → 出身记忆 → 状态卡 → 年记 → 月记 → 周记 → 日记 →
  环境状态 → 会话历史 → 尾部块。尾部块收纳逐轮必新的内容（精确当前时刻等），置于最新用户消息旁；环境状态随会话快照冻结并粗粒度化，避免逐轮变化打穿前缀缓存、使会话历史全价重算。
-
环境状态槽由代码计算填充并随会话快照冻结：日期、星期、配置时区与系统时区不一致时的"用户可能在旅行/出差"提示等粗粒度信息；精确当前时刻归尾部块。后续天气、节假日等同理并入（按变动频率归位）。
- 心境从状态区读取，模块内不做任何随机。
- 人设包为角色内容的打包单元：元信息 + 人设核心 + 世界观块 + 性格池（性格、权重、参考语料）+ 场景覆盖 +
  记忆槽位。性格池属于人设包，各角色各自持有；人设包只能向全局层加内容，不能卸。
- 人设包文件格式为数据目录下的目录包 `personas/<id>/`：`manifest.yaml`（元信息、格式版本、文件索引、性格池、场景覆盖）+
  `core.md`（人设核心）+ `worldview/*.md`（世界观块，一文件一块）+ `corpus/*.md`（参考语料）+ `memories.yaml`（记忆槽位）；大段文本用
  Markdown、结构化部分用 YAML；导入导出为 zip。
- 人设包权威存储为文件系统：引擎启动/切换时将激活人设包完整加载进内存，UI 编辑经引擎 API 写穿（更新内存并同步写回文件）；SQLite
  只存激活指针等运行状态。人设包是内容创作物，与 .env 同为「单一 SQLite 承载全部运行数据」的例外。
- 记忆槽位承载角色出身记忆（开箱即有的往事与关系初始设定），带分区标签；作为常驻注入块组装，位置在人设块之后、状态卡之前（见组装顺序）。出身记忆不进记忆系统：不入库、不参与检索（常驻注入即始终在上下文中），体积由人设包规范设建议上限。
- 每轮组装结果落盘到独立日志（见横切关注点）。

### 记忆模块

结构：分区 × {四层笔记、向量库} + 状态区。

分区不变式（全系统唯一规则）：任何数据带公开/隐私标签；公开数据注入所有会话，隐私数据仅注入私聊。适用于会话历史、四层笔记、向量库、状态区，以及
AI 主动检索工具的返回结果。写入时条目默认继承产生它的会话的分区；AI 可显式将隐私内容升级为公开。

四层笔记（时间轴金字塔，逐层压缩）：

- 日记：最近 24 小时条目的滚动窗口，是纯查询视图而非存储实体；窗口平滑移动，无定稿时刻，避免"横跨定稿时刻突然失忆"的悬崖。
- 周记/月记/年记：压缩后的行集合，条目带简化描述、重要度评分与 `anchored_to` 锚点（指回来源条目，支持逐层下钻还原）。
- 晋升在条目滑出 24h 窗口前完成，避免既不在日层也不在周层的空窗。
- 重要度评分用于压缩时决定条目存活，不用于动态调整上限；各层上限初版固定（周记软 30 条 / 硬 40 条）。
- 压缩时判定为用户/关系的持久事实走侧向出口沉淀进状态卡，年记只留叙事史（当前事实归状态卡与向量库，防止多副本漂移）。
- 永不删除：append-only，压缩产生新行。
- 遗忘语义：条目滑出日层且晋升被拒，即退出所有注入层（仍可主动检索）。

向量库（语义索引）：

- AI 自主存取；存储判据是"以后会经常通过关键字召回"，条目须含可检索的具体内容，不存空泛总结，禁止存状态卡类持久事实（唯一权威在状态卡）。
- 存前查重，命中则更新：重写合并后的条目，元数据日期列表追加而非覆盖；距离落在灰区带的交 LLM 仲裁是否同一件事，阈值与带宽进配置。
- 定位是当前信念，事实变更改此处；历史轨迹由笔记承载。
- 元数据记录关联日期，供回查对应日记；检索结果携带关联日期（按配置时区渲染，长列表压为首末日期 + 次数）。
- 检索查询由 AI 经工具自行构造，不取用户消息原文做自动查询；排序合成相关度、新近度衰减与重要度，重要度与时间以 INTEGER/FLOAT
  元数据列存储。
- 检索命中即强化：更新最后访问时间并微增重要度；长期零命中、低重要度且久远是记忆卫生的低质清理判据。
- 记忆卫生含对账：向量条目与状态卡冲突时以状态卡为准改写，实为持久事实的条目晋升进状态卡（侧向出口）。
- 向量引擎为 sqlite-vec（vec0 虚拟表，cosine 距离）：分区标签做元数据列，条目原文做辅助列，主键关联记忆条目；检索为精确暴力
  top-k，不用 ANN（查重的阈值判断依赖精确召回）。
- 全项目单一嵌入模型，不更换（红线）：fastembed（ONNX CPU）运行 jinaai/jina-embeddings-v2-base-zh（768 维）。

状态区：

- 公开块：心境（每日抽取的主/次性格结果）等角色自身状态；
- 隐私块：用户卡（姓名、职业、宠物等持久事实）、关系状态；
- 分区标签落到条目级：用户卡、关系状态中可公开提及的最小事实（用户昵称、关系存在性等）可逐条标公开，`sns_*`
  场景下角色因此知道关系存在但不谈隐私细节；
- 常驻注入，AI 可经工具修改。

注入与检索：

- 每轮组装的常驻内容：人设 + 状态卡 + 四层笔记（控字数）+ 环境状态 + 会话历史；向量库不自动注入，召回由 AI
  经检索工具拉取，近期与重要内容由常驻注入兜底。提示词写明检索触发指引（会话开始结合触发上下文、提及过去的人/事/约定时应当检索）。
- 记忆读写工具化：按日期查笔记、语义检索、存/改向量条目、改状态卡，走插件工具协议，返回结果过分区过滤。
- 注入体积与库大小解耦：注入由窗口与上限封顶，数据增长不转化为上下文成本。

### LLM 模块

- 现役模型：`deepseek-flash`（V4.1-Flash，支持视觉）、`deepseek-v4-pro`（Agent 能力增强）。旧名 `deepseek-chat` /
  `deepseek-reasoner` 已停用，不使用。
- 客户端实现：不引入 LangChain 等 agent 框架（agent loop 归对话引擎自研），本模块为自写薄封装；传输层用 openai 官方 SDK 指向
  DeepSeek（自定义 base_url，`thinking` 等 V4 扩展参数经 `extra_body` 传递，SDK 版本钉死）。API 面走 Chat Completions（
  `chat.completions.create`）：V4 参数、缓存命中统计、reasoning_content 回传规则均以该面为准，消息行三字段与整轮裁剪即其形状；不采用
  Responses API（DeepSeek 侧为无状态兼容层，无服务器端会话与内建工具收益，实现不完整）与 Anthropic 兼容端点（面向 Claude Code
  生态，特性滞后且丢失本地模型逃生通道）。
- 对引擎暴露自有事件流接口（文本增量 / reasoning 增量 / tool_call 增量 / 用量统计 / 结束），引擎不感知 SDK 类型与具体 API
  面；测试用 FakeLLM 实现同一接口，底层 httpx 客户端经构造函数注入。
- 场景级配置维度：模型 × thinking 开关 × effort（low/high/max）× 是否附带 tools。日常闲聊用 flash + 低档思考或关闭思考，插件/Agent
  密集轮次用高档或 pro。后台任务调用另设独立配置组，不经场景枚举。
- thinking 模式 CoT 回传规则（API 行为）：
    - 请求不带 `tools`：`reasoning_content` 无须回传，传入也会被忽略；
    - 请求带 `tools`：所有历史轮次的 `reasoning_content` 必须完整回传，否则 400。
- 会话消息行结构：`content` + `reasoning_content` + `tool_calls` 三字段并存；带 tools 的会话必须完整保存思维链。
- 回传窗口的组装权归本模块：引擎提供消息列表与裁剪意图，本模块按 API 规则组装最终请求。
- 利用上下文缓存（命中价约为未命中的 1/50），配合提示词模块的稳定前缀排序。
- 计费有峰谷之分，无时效性后台任务排谷时段。
- 职责还包括重试/超时/限流与用量统计；对外暴露 token 计数，裁多少的决策归对话引擎。
- 抽象上预留本地模型运行的可能，当前仅实现 API 路径；OpenAI 兼容协议即逃生通道（vLLM / Ollama 等同协议服务），换 base_url
  即可接入。

### 插件模块

- 定位是对话引擎的协作者：引擎解析 tool_call 后分发执行、结果回填对话；不是独立的顶层调用方。
- 每个插件是自包含单元：实现 + 给模型看的 tool schema + manifest 声明；引擎只做注册与分发。加载方式为启动扫描 + manifest
  注册 + 重载，不做运行时热替换。
- 安全约束：危险操作（shell 等）白名单 + 确认门；插件输出加隔离标记，防外部文本（网页内容等）的提示注入指挥危险操作；执行设超时。
- 网页浏览类插件可基于 DeepSeek 官方 Search/Fetch API 实现。

### 交互层

薄前端，只管用户输入与输出展示。形态为「引擎进程 + 多前端客户端」：引擎以 asyncio 单进程运行并内置 API 服务（protobuf 契约 +
ConnectRPC），桌面 pywebview 壳与移动端浏览器 / PWA 均为该服务的客户端，前端不直接触碰引擎与存储；引擎可脱离前端 headless
常驻部署（NAS / 服务器）。设计细节见 [ui_design.md](ui_design.md)。

### 存储层

单一 SQLite 承载全部持久化，是所有运行数据的唯一落盘位置；人设包等内容文件存于数据目录（格式与存储见提示词模块），SQLite
内只存其激活指针等运行状态。

- 模式：WAL + busy_timeout；笔记条目表建 `(partition, layer, ts)` 复合索引。
- 写入模式：append-only，只插不改不删，压缩产生新行；无删除碎片，不需要 VACUUM。
- 主要表：原始会话历史（分区标签 + 三字段消息 + 元数据信封）、四层笔记条目（含锚点与重要度）、调度项、状态区、向量索引（sqlite-vec
  vec0 虚拟表，与主库同文件）。主要表建表即带 `persona_id` 列：运行时初版单激活角色，切换人设即记忆、心境、关系状态、调度项整套随
  persona 隔离；多角色留待后续扩展，届时免数据迁移。
- 时间：统一存 UTC epoch；展示层按配置时区（IANA 名称，zoneinfo 处理夏令时）渲染；"某一天"类查询按配置时区日界线换算成 UTC
  区间。配置时区变更会回溯改变历史日切片，属预期语义。
- 完整提示词组装日志不进主库：独立滚动文件 + 压缩（或采样）。
- 容量：重度使用（200 次对话/天，含元数据与思维链）全年数百 MB 量级，远低于 SQLite 能力上限。
- 备份：单文件复制，或定期 `VACUUM INTO` 出紧凑副本。

## 横切关注点

- 配置与密钥：DeepSeek API key 等经环境变量 / .env 注入，不进仓库。
-
可观测：每轮完整提示词独立日志落盘；心境抽取、重要度评分分布、晋升决策、记忆检索与查重仲裁落日志，支持排查"它为什么这么说"；维护固定基线问题集，阈值/嵌入输入变更后重放对比。
- token 预算：常驻注入（人设 + 记忆 + 历史）统一预算管理。
- 并发：单进程 asyncio；后台任务与引擎并发访问 SQLite 由 WAL 承接。
- 可测性：时钟、LLM 客户端、嵌入函数、数据库路径一律经构造函数注入，供测试替换；测试设计见 [testing.md](testing.md)。
